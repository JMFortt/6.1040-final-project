# Rubric: professionalism

Original: https://61040.github.io/fa26/rubrics/professionalism/

## Qualities

- **Accessible.** A reader can use the submission as delivered, from instructions that were tried. It is self-contained. It does not depend on the author’s machine or on unstated knowledge. A fresh clone of a code repo runs from the README, without secrets or hardcoded local paths.
- **Organized.** Structure follows ordinary conventions. A short overview explains the work and links to its parts. Nothing extraneous is included. The repo root is clean. Git history shows incremental progress and meaningful commit messages.
- **Readable.** Written for human readers. Consistent names and formatting. No placeholders or leftover drafts. Dead code and debug output are gone. Generated code has been reviewed.

## Pitfalls

Hidden dependencies. Instructions that are incomplete, stale, or false. Placeholders, scratch files, abandoned drafts, dead code, or unreviewed generated material. Parts that are fine on their own while the overview never says what the work is. Anonymity: authors of a written or oral presentation introduce themselves unless there is a real reason not to.

## Levels

- **Deficient** — cannot be used or understood without the author, or the overview and instructions are missing
- **Emergent** — some structure; readers must guess or fix important details; instructions are incomplete or stale; leftovers are widespread
- **Competent** — usable as documented; organized and readable; clear overview; working instructions; only minor leftovers
- **Expert** — meets competent, and is unusually easy to navigate, understand, and reproduce
